# Cross-SDK conformance for the 2026-11 feature-parity round

Thirteen SDK PRs port three javascript-sdk features to every SDK, each on its
`feat/assignment-rules-semver-x-agent-publish` branch (java-sdk#22 and the
javascript-sdk#68 reference already had the first two). `sdk-branches.sh` pins
those branches. This document lists what scenarios 300-321 pin. They are
generated by `generate_parity_round_scenarios.py`.

## Oracle

The assignment-rules and semver expectations are the real output of
javascript-sdk#68 (`feat/sdk-system-attributes`, commit pinned in
`generate_sdk_round_2026_11_scenarios.py`), run through
`tools/sdk-round-2026-11/compute.js`. Seeds and units for split rules were picked
with the reference `VariantAssigner` so that each pinned variant differs from the
traffic-seed, swapped-seed, zero-seed and normal-split results.

The X-Agent group is the exception: the reference sends the unversioned
`absmartly-javascript-sdk`, so the expectation is the round's contract,
`absmartly-<lang>-sdk/<semver>`, asserted with a regex. `<lang>` must name the
SDK under test and `<semver>` must follow the semver.org 2.0.0 grammar. The
JS-family lanes list `xAgentHeader` as a reviewed exception.

The 2026-11 round groups (230-245) cover the basics these build on: assign rule
wins, override beats a rule, rule over strict audience and custom assignment,
variable values through a rule, out-of-range variants and the removed-experiment
rebuild.

## Harness support

`capturedRequests` reads the requests a wrapper's mock collector recorded
(`GET /context_payload/{id}/requests`), and `createContext` forwards
`publishToEndpoint` so the SDK publishes through its own HTTP client to
`PUT {endpoint}/context`. See WRAPPER_API_SPEC.md section 2b-i.

## Generators

`generate_sdk_round_2026_11_scenarios.py` owns 230-253 and
`generate_parity_round_scenarios.py` owns 300-321. Each regenerates only its own
groups and leaves the other's where they are, so both `--check` runs pass on the
same file (pinned by `ScenarioGeneratorsCoexistTest` in `tests/test_harness.py`).
